# 🛠️ Taller MVP — construir software vendible mientras practico

Carril paralelo al empleo: aquí construyo mi propio software real, con sentido comercial, para **practicar el stack que aún no domino** (FastAPI, Docker, cloud, LLMs, APIs) y a la vez tener una **segunda carta de presentación** para reclutadores.

## Reglas del taller

1. **Un usuario que pague al mes = éxito de validación.** No busco hacerme rico; busco probar que alguien paga por algo que yo construí. Esa sola frase en una entrevista vale oro.
2. **Barrera de pago mínima.** Precio "ganga" hasta validar. Freemium o pago-por-uso. El objetivo temprano es el *primer dólar*, no el ingreso grande.
3. **Calidad siempre.** Aunque sea práctica, nada cutre: es portafolio. README serio, código limpio, contenedores, deploy real.
4. **Trabajo por sprints.** Ciclos cortos (1–2 semanas) con un objetivo y un entregable demostrable. Ver `TABLERO.md`.
5. **Todo commiteado.** Cada avance = commit fechado (respalda mi bitácora y mi experiencia).

## Estructura

```
Taller_MVP/
├── README.md            ← este archivo
├── IDEAS.md             ← backlog de ideas (rankeadas)
├── TABLERO.md           ← kanban + objetivo del sprint actual
├── _PLANTILLA_ticket.md ← copia por cada tarea
└── <proyecto>/          ← cuando elijas la idea, aquí vive el código (repo aparte en GitHub)
```

## Flujo

**Elegir idea (IDEAS.md) → definir Sprint 0 (TABLERO.md) → crear tickets → construir → deploy → conseguir el primer usuario → iterar.**

Ver el **Documento 06 (`06_Taller_MVP_Ideas_y_Sprints.docx`)** para la mentalidad, las ideas explicadas, la arquitectura recomendada y los sprints concretos.
