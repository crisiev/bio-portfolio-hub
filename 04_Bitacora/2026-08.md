- **🛠️ Qué hice:** (1) Descargada muestra FASTQ y resuelto error forense de archivo no comprimido en disco (`mv` + `gzip -f`). (3) Navegado de forma fluida e interactiva con `zless -S`. (4) Extraídas cabeceras (`awk 'NR%4==1'`) y secuencias (`awk 'NR%4==2'`). (5) Filtrado y contado lecturas con motivo `TTGGC` usando `grep` en stream. (6) Calculada longitud en pares de bases (`wc -c` descontando salto de línea `\n`).
- **💻 Comandos Útiles del Día (Recetario CLI):**
  ```bash
  # 1. Renombrar y comprimir correctamente a formato gzip real
  mv ecoli_reads.fastq.gz ecoli_reads.fastq
  gzip -f ecoli_reads.fastq
  file ecoli_reads.fastq.gz

  # 2. Inspeccionar primeras 12 líneas (3 lecturas de 4 líneas cada una)
  zcat ecoli_reads.fastq.gz | head -n 12

  # 3. Navegación interactiva fluida sin desajustar líneas (presionar 'q' para salir)
  zless -S ecoli_reads.fastq.gz

  # 4. Contar líneas totales del archivo comprimido
  zcat ecoli_reads.fastq.gz | wc -l

  # 5. Extraer únicamente los IDs/headers (Línea 1 de cada ciclo de 4)
  zcat ecoli_reads.fastq.gz | awk 'NR%4==1'

  # 6. Extraer únicamente las secuencias de ADN (Línea 2 de cada ciclo de 4)
  zcat ecoli_reads.fastq.gz | awk 'NR%4==2'

  # 7. Buscar un motivo específico ("TTGGC") dentro de las secuencias de ADN
  zcat ecoli_reads.fastq.gz | awk 'NR%4==2' | grep "TTGGC"

  # 8. Contar cuántas lecturas contienen dicho motivo
  zcat ecoli_reads.fastq.gz | awk 'NR%4==2' | grep "TTGGC" | wc -l

  # 9. Calcular la longitud de bases de la primera lectura (26 bytes menos 1 salto de línea = 25 bp)
  zcat ecoli_reads.fastq.gz | awk 'NR%4==2' | head -n 1 | wc -c
  ```
- **📚 Qué aprendí:** 
  1. **Anatomía del FASTQ & Phred+33:** El estándar FASTQ es un ciclo estricto de 4 líneas (1: `@Header`, 2: Secuencia, 3: `+`, 4: Calidad ASCII). La calidad Phred se calcula como $Q = -10 \log_{10}(P_{\text{error}})$. Para almacenarlo en un solo byte se suma el offset 33 de ASCII ($Q = \text{ASCII} - 33$). Por ejemplo, el símbolo `;` (ASCII 59) representa $Q = 26$ (99.75% de certeza).
  2. **Streaming & Buffers en Unix:** La tubería `|` transfiere bytes directamente del búfer `stdout` de `zcat` al `stdin` de `head`/`awk`. Al recibir `head` las líneas solicitadas, envía una señal `SIGPIPE` que detiene la descompresión sin saturar RAM ni I/O de disco.
  3. **Magic Bytes & Diagnósticos CLI:** La extensión de archivo es cosmética en Linux. `zcat` exige los bytes mágicos `1f 8b`. Archivos descargados en texto plano con extensión `.gz` causan el fallo `not in gzip format`, resolviéndose comprimiendo con `gzip -f`.
  4. **Procesamiento Cíclico en `awk`:** El operador módulo `NR%4` permite aislar componentes específicos del FASTQ (`NR%4==1` para headers, `NR%4==2` para secuencias, `NR%4==0` para calidades).
  5. **Arquitectura Multi-OS & Métrica Dual:** El proyecto usa una arquitectura Dual-Clone (Windows host en `C:\Users\...` para IDE/gobernanza y WSL ext4 en `/home/admin/empleoBio` para ejecución de comandos). La métrica **85 XP** representa Puntos de Rango técnico de La Campaña (no dólares USD del Taller MVP).
  6. **Alias de Bash & Entornos de Conda:** Los alias persistentes se configuran en `~/.bashrc` (ej. `alias sync-repo='cd ~/empleoBio && git pull origin main'`). Al ejecutar `source ~/.bashrc`, el shell recarga el perfil reiniciando la pila de Conda al entorno `(base)`. Para volver a las librerías bioinformáticas se ejecuta `conda activate bio-env`. Los alias y Git funcionan independientemente de cuál entorno virtual de Python esté activo.
